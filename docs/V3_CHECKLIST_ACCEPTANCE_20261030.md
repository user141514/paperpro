## 版本与正确性约束

`不可变原件 → 经确认的草稿 → 冻结的要求与诊断 → 有依据的建议 → 用户实际修改与独立完成 → 同一版本导出`。这是本轮的验收链；单个请求返回 200 不代表整条链通过。

任务、原件、输入修订、运行、建议和导出都有独立标识。输入改变后旧报告保留为历史；只改变导航步骤不使报告失效。发布新运行会推进任务修订号，旧页面不能用旧修订修改新运行的同名建议。单模块重试保留其他模块结果和不受影响的待办；受影响的修改保留文字并要求重新确认。恢复历史输入产生新修订，不删除后来的记录。

原文位置只在字面唯一、值未更改且结构可靠时给精确字符范围。人工更正、重复文本、删除或结构变化使用待核对标记，展示已有原文摘录；不伪造 PDF/图片坐标。取消会在处理阶段间阻止后续解析和模块运行；已进入的原生 OCR 不强杀，其迟到结果不能发布为当前。

## 验证边界

- 合成数据和 Chrome 自动化证明功能状态及边界，不证明真实 HR 评分效度、真实手机 OCR 准确率或真人样本字段完整率。
- 本轮没有训练或部署新解析模型。原有复杂版式挑战集 167/276（60.51%）和合成图片 49/52（94.23%）是历史测量，不能写成本轮提升。
- 通用岗位规则和有限词表不是任意 JD 的语义理解器；无官方 JD 时明确显示通用来源。分数是当前书面证据覆盖度，不是录用概率。
- F10 的字段级最小重算尚未实现：当前上游输入编辑会将旧报告整体转为需重检，重新冻结完整快照；失败模块的单项重试已经保留其他模块和不受影响的待办。未发现只改表达导致错年限或错版的反例，但不能将当前行为表述为已实现精确依赖差分。
- 本轮的 PDF 报告使用中文报告布局。无法可靠呈现的非 BMP 字符会提示使用 TXT；不静默输出缺字文件。
- 旧版 DOC/经典 Word PDF 依赖本机 Word COM。全量回归中该路径可能打印既有 Windows RPC 异常，测试通过不代表原生 COM 完全无故障。
