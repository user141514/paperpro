## 版本与正确性约束

`不可变原件 → 经确认的草稿 → 冻结的要求与诊断 → 有依据的建议 → 用户实际修改与独立完成 → 同一版本导出`。这是本轮的验收链；单个请求返回 200 不代表整条链通过。

任务、原件、输入修订、运行、建议和导出都有独立标识。输入改变后旧报告保留为历史；只改变导航步骤不使报告失效。发布新运行会推进任务修订号，旧页面不能用旧修订修改新运行的同名建议。单模块重试保留其他模块结果和不受影响的待办；受影响的修改保留文字并要求重新确认。恢复历史输入产生新修订，不删除后来的记录。

原文位置只在字面唯一、值未更改且结构可靠时给精确字符范围。人工更正、重复文本、删除或结构变化使用待核对标记，展示已有原文摘录；不伪造 PDF/图片坐标。取消会在处理阶段间阻止后续解析和模块运行；已进入的原生 OCR 不强杀，其迟到结果不能发布为当前。

## 验证边界

- 合成数据和 Chrome 自动化证明功能状态及边界，不证明真实 HR 评分效度、真实手机 OCR 准确率或真人样本字段完整率。

- 本轮的 PDF 报告使用中文报告布局。无法可靠呈现的非 BMP 字符会提示使用 TXT；不静默输出缺字文件。
- 旧版 DOC/经典 Word PDF 依赖本机 Word COM。全量回归中该路径可能打印既有 Windows RPC 异常，测试通过不代表原生 COM 完全无故障。

## 字段级最小重算补齐（2026-10-30）

因果链：识别真实字段依赖 → 只执行受影响模块 → 当前汇总与全量计算等价 → 用户保留有效结果和实际修改，并导出同一版本材料。模块指纹是可重建的派生值，保存于既有不可变运行快照；SQLite 继续独占任务、版本、运行、采纳与完成的接受权，没有另建缓存数据库或后台服务。

下表以当前通用岗位模型的全因素要求、五个上一份模块均成功为例；只启用部分能力因素时，岗位匹配的依赖还能进一步缩小。

| 编辑内容 | 实际重算 | 可复用 |
|---|---|---|
| 仅修改联系方式 | 无；仅重建当前汇总和快照 | 五个成功模块 |
| 仅调整确认后的要求权重，合计仍为 100% | 岗位匹配 | 其余四个模块 |
| 个人概述 | 岗位匹配、求职针对性、面试核查 | 经历与时间、发展潜力 |
| 工作职责文字 | 岗位匹配、发展潜力、求职针对性、面试核查 | 经历与时间 |
| 独立任职起止日期 | 经历与时间、面试核查；岗位匹配含经验因素时也重算 | 发展潜力、求职针对性 |
| 目标公司 | 求职针对性 | 其余四个模块 |
| 目标职位 | 岗位匹配、求职针对性 | 其余三个模块 |
| 统计基准日 | 经历与时间、面试核查；岗位匹配含经验因素时也重算 | 发展潜力、求职针对性 |
| 关闭／再次开启一个模块 | 关闭时不执行；再次开启只执行该模块 | 其他依赖未变的模块 |

岗位匹配按**已确认的能力因素**进一步缩小依赖；只评技能、学历或证书时不会因为独立任职日期变化重算。原始 JD 影响要求整理和求职针对性；确认后的匹配计算以用户核对过的逐项要求为准。增删、重排经历或证据会改变路径及引用，不能用旧路径证明新内容。验证模块保留原冲突检查“先取前 350 条引用、再筛 scope”的边界，标题等字段对该截断边界的影响也有反例覆盖。

旧汇总在输入改变后仍标记需重新检查，不能采纳或作为当前报告导出；未受影响模块可以只读查看。重新检查完成后，新的建议、核查问题、输入哈希与导出始终从当前快照重建。前端只投影后端给出的范围，不另外复制依赖逻辑。报告记录实际执行范围、直接来源和最初计算来源；页面可打开既有只读历史，TXT/PDF 分别显示原计算基准日与本次核对基准日。
